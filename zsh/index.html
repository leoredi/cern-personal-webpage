A minimal zsh

Four files, about 150 lines, and why I threw away everything else.

Why

Last weekend I wiped my MacBook and did not restore the old setup (fish, iTerm2 tweaks, conda). Half of my commands are now run by an AI agent [0], and agents want a boring shell. Four files, and basta.

The same files now also run on my Ubuntu ThinkPad. Where the two systems differ (Homebrew, ls colours, where the plugins live) the files check $OSTYPE and do the right thing, so there is one copy to maintain, not two.

The idea

zsh reads different files depending on how it is started [1]. The trick is just to put each thing in the right one:

FileRead byWhat goes in
~/.zshenvevery zsh, agents includedPATH, Homebrew (if any), language, editor. Nothing else.
~/.zprofilelogin shells (new terminal window, ssh)macOS only: puts Homebrew back in front, because macOS moves /usr/bin ahead of it. Does nothing on Linux.
~/.zshrcinteractive shells, so humansCompletion, history, keys, prompt, aliases, two plugins.
~/.bash_profilebash login shellsmacOS only: one line, so agents that call bash also find Homebrew. On Ubuntu the tools are in /usr/bin anyway.

Claude Code exports CLAUDECODE=1 in every command it runs, so my .zshrc stops at line 5 when it sees it. Other agents that run zsh -c do not read .zshrc at all. In both cases the agent gets my PATH and nothing of my taste.

Left out

What is not there is more important than what is there:

  • No framework, no plugin manager, no theme. The two plugins (autosuggestions and syntax highlighting) come from Homebrew on macOS or apt on Ubuntu, and are skipped if they are not installed.
  • No setopt correct. The “nyae?” prompt blocks agents and, to be honest, annoys also me.
  • No aliases that redefine ls, cat, grep or rm. Only new names (ll, la, mkcd…), so scripts and agents see the standard tools.
  • No Homebrew in front of the system on Linux. If linuxbrew is installed it goes at the end of PATH, so python3, git & co. are the apt ones the agent expects.
  • No conda. Python lives in a .venv per project, managed by uv [2].
  • No ROOT, Geant4 or LCG views sourced at startup. They are slow and they change the environment of every single command. When I need them I type rootenv or g4env.

Files

Here they are. Download them, read them (please do!), change what you don’t like.

~/.zshenvdownload

# ~/.zshenv — read by EVERY zsh (login, interactive, and `zsh -c` from agents).
# Keep it tiny: environment only. No aliases, no prompt, no plugins.
# Works on macOS and Ubuntu.

export LANG=${LANG:-en_GB.UTF-8}
export EDITOR=vim          # change to `code -w` / `nvim` if you prefer
export VISUAL="$EDITOR"
export PAGER=less
export LESS=-FRX           # quit if one screen, keep colours, don't clear

# PATH as an array with no duplicates
typeset -U path PATH
path=("$HOME/.local/bin" $path)

# Homebrew, if present: macOS (Apple Silicon or Intel) or Linux (linuxbrew)
for _b in /opt/homebrew /usr/local /home/linuxbrew/.linuxbrew; do
  [[ -x $_b/bin/brew ]] || continue
  if [[ $OSTYPE == darwin* ]]; then
    eval "$($_b/bin/brew shellenv)"          # macOS: brew tools first
  else
    export HOMEBREW_PREFIX=$_b               # Linux: apt tools first,
    path=($path $_b/bin $_b/sbin)            # brew only fills the gaps
  fi
  break
done
unset _b
export HOMEBREW_NO_ENV_HINTS=1

# Do NOT source ROOT / Geant4 / LCG setup scripts here. They are slow and
# they change the environment every agent command runs in. Use the
# `rootenv` / `g4env` functions in ~/.zshrc instead, when you need them.

~/.zprofiledownload

# ~/.zprofile — login shells only (Terminal.app, iTerm, ssh).
# macOS runs /etc/zprofile -> path_helper, which pushes /usr/bin ahead of
# Homebrew. Re-assert Homebrew here so `brew` tools win. Harmless if repeated.
# On Linux this file does nothing.
if [[ $OSTYPE == darwin* ]]; then
  if [[ -x /opt/homebrew/bin/brew ]]; then
    eval "$(/opt/homebrew/bin/brew shellenv)"
  elif [[ -x /usr/local/bin/brew ]]; then
    eval "$(/usr/local/bin/brew shellenv)"
  fi
fi

~/.zshrcdownload

# ~/.zshrc — interactive shells only. Agents running `zsh -c` never read this.

# ---- Bail out early for AI agents ---------------------------------------
# Claude Code exports CLAUDECODE=1. Anything after this line is for humans.
[[ -n "$CLAUDECODE" ]] && return
[[ -o interactive ]] || return

# ---- Completion ----------------------------------------------------------
# Homebrew puts completions (brew, git, gh, docker, cmake, ...) here.
# brew shellenv does NOT add this to fpath, so do it by hand, before compinit.
# (On Ubuntu, apt packages already install theirs in the default fpath.)
if [[ -n "$HOMEBREW_PREFIX" ]]; then
  fpath=("$HOMEBREW_PREFIX/share/zsh/site-functions" $fpath)
fi
setopt extended_glob            # needed for the (#q...) qualifier below
autoload -Uz compinit
# Rebuild the dump once a day, otherwise use the cache (fast startup)
if [[ -n ${ZDOTDIR:-$HOME}/.zcompdump(#qN.mh+24) ]]; then
  compinit
else
  compinit -C
fi
zstyle ':completion:*' menu select                       # arrow-key menu
zstyle ':completion:*' matcher-list 'm:{a-zA-Z}={A-Za-z}' # case-insensitive
zstyle ':completion:*' list-colors "${(s.:.)LS_COLORS}"
zstyle ':completion:*:descriptions' format '%F{yellow}-- %d --%f'
zstyle ':completion:*' use-cache on
zstyle ':completion:*' cache-path "$HOME/.cache/zsh/compcache"
mkdir -p "$HOME/.cache/zsh"

# ---- History -------------------------------------------------------------
HISTFILE="$HOME/.zsh_history"
HISTSIZE=100000
SAVEHIST=100000
setopt extended_history        # timestamps
setopt hist_ignore_all_dups    # drop older duplicates
setopt hist_ignore_space       # " cmd" is not recorded
setopt hist_reduce_blanks
setopt share_history           # shared across open terminals
setopt inc_append_history

# ---- Options -------------------------------------------------------------
setopt auto_cd                 # type a directory name to cd into it
setopt auto_pushd pushd_ignore_dups pushd_silent
setopt interactive_comments    # allow # comments on the command line
setopt no_beep
setopt extended_glob
# Deliberately NOT set: correct / correct_all (the "nyae?" prompt hangs agents
# and annoys humans), noclobber, rm_star_silent tricks.

# ---- Keys ----------------------------------------------------------------
bindkey -e                                       # emacs keys (vanilla)
autoload -Uz up-line-or-beginning-search down-line-or-beginning-search
zle -N up-line-or-beginning-search
zle -N down-line-or-beginning-search
bindkey '^[[A' up-line-or-beginning-search       # Up: history matching prefix
bindkey '^[[B' down-line-or-beginning-search     # Down
bindkey '^[[1;3C' forward-word                   # Alt+Right
bindkey '^[[1;3D' backward-word                  # Alt+Left
bindkey '^[[3~' delete-char                      # Fn+Delete

# ---- Aliases (additive only: never redefine ls, cat, grep, rm, ...) ------
if [[ $OSTYPE == darwin* ]]; then
  export CLICOLOR=1; _c=''                       # colour for BSD ls
else
  eval "$(dircolors -b)"; _c=' --color=auto'     # colour for GNU ls
fi
alias ll="ls -lhF$_c"
alias la="ls -lahF$_c"
alias l="ls -F$_c"
unset _c
alias ..='cd ..'
alias ...='cd ../..'
alias ....='cd ../../..'
alias -- -='cd -'
alias md='mkdir -p'
alias path='print -l $path'
(( $+commands[brew] )) && alias brewup='brew update && brew upgrade && brew cleanup'
[[ -r /etc/debian_version ]] && alias aptup='sudo apt update && sudo apt full-upgrade -y && sudo apt autoremove -y'
mkcd() { mkdir -p "$1" && cd "$1"; }

# HEP environments, on demand only (edit the paths to match your installs)
rootenv() { source "${1:-$HOMEBREW_PREFIX}/bin/thisroot.sh" && echo "ROOT $(root-config --version)"; }
g4env()   { source "${1:-$HOMEBREW_PREFIX}/bin/geant4.sh"  && echo "Geant4 ready"; }

# ---- Prompt (single line, git branch, nothing on the right) --------------
autoload -Uz vcs_info
zstyle ':vcs_info:git:*' formats ' %F{magenta}%b%f%c%u'
zstyle ':vcs_info:git:*' actionformats ' %F{magenta}%b|%a%f'
zstyle ':vcs_info:git:*' check-for-changes true
zstyle ':vcs_info:git:*' stagedstr '%F{green}+%f'
zstyle ':vcs_info:git:*' unstagedstr '%F{red}*%f'
precmd() { vcs_info }
setopt prompt_subst
PROMPT='%F{cyan}%1~%f${vcs_info_msg_0_} %(?.%F{green}.%F{red})%#%f '

# ---- Optional plugins (purely visual, skipped if absent) ----------------
# macOS:  brew install zsh-autosuggestions zsh-syntax-highlighting
# Ubuntu: sudo apt install zsh-autosuggestions zsh-syntax-highlighting
for _d in "$HOMEBREW_PREFIX/share" /usr/share; do
  [[ -r $_d/zsh-autosuggestions/zsh-autosuggestions.zsh ]] || continue
  source $_d/zsh-autosuggestions/zsh-autosuggestions.zsh; break
done
ZSH_AUTOSUGGEST_STRATEGY=(history completion)
# syntax highlighting must be sourced LAST
for _d in "$HOMEBREW_PREFIX/share" /usr/share; do
  [[ -r $_d/zsh-syntax-highlighting/zsh-syntax-highlighting.zsh ]] || continue
  source $_d/zsh-syntax-highlighting/zsh-syntax-highlighting.zsh; break
done
unset _d

# ---- Machine-local extras (not in git) ----------------------------------
[[ -r "$HOME/.zshrc.local" ]] && source "$HOME/.zshrc.local"

install.shdownload

#!/bin/sh
# One-shot install for macOS or Ubuntu. Backs up anything it overwrites.
# Run with plain sh: on a fresh Ubuntu zsh is not there yet.
set -e
cd "$(dirname "$0")"
case "$(uname)" in
  Darwin)
    # zsh and vim ship with macOS; plugins are optional eye candy
    if command -v brew >/dev/null; then
      brew install zsh-autosuggestions zsh-syntax-highlighting
      # make Homebrew visible to agents that use bash (Claude Code often does)
      grep -q 'brew shellenv' "$HOME/.bash_profile" 2>/dev/null ||
        echo "eval \"\$($(command -v brew) shellenv)\"" >> "$HOME/.bash_profile"
    fi ;;
  Linux)
    sudo apt-get install -y zsh vim zsh-autosuggestions zsh-syntax-highlighting
    [ "$(getent passwd "$USER" | cut -d: -f7)" = /usr/bin/zsh ] ||
      chsh -s /usr/bin/zsh ;;
esac
for f in zshenv zprofile zshrc; do
  [ -e "$HOME/.$f" ] && mv "$HOME/.$f" "$HOME/.$f.bak.$(date +%Y%m%d%H%M%S)"
  cp "$f" "$HOME/.$f"
done
# refresh completion cache
rm -f "$HOME/.zcompdump"*
echo "Done. Log out and in (Linux) or open a new terminal, or: exec zsh"

Install

mkdir minimal-zsh && cd minimal-zsh
for f in zshenv zprofile zshrc install.sh; do
  curl -fsSLO https://fredi.web.cern.ch/zsh/$f
done
less zshrc          # read before running, always
sh install.sh        # plain sh: on a fresh Ubuntu zsh is not there yet

The script makes a backup of every file it overwrites (.zshrc.bak.<date>). On macOS it installs the two plugins if you have Homebrew and adds one line to .bash_profile. On Ubuntu it asks for your password once, installs zsh, vim and the two plugins with apt, and makes zsh your login shell with chsh.

Then open a new terminal (on Ubuntu, log out and back in first, so the new login shell takes effect). On a Mac which brew should print /opt/homebrew/bin/brew; on Ubuntu echo $SHELL should print /usr/bin/zsh. Inside Claude Code, echo $CLAUDECODE should print 1. Anything machine-specific goes in ~/.zshrc.local, which is read at the end if it exists.

Optional: fingerprint for sudo only. An agent cannot type your password, but you can touch a sensor. If you allow fingerprint for sudo, you can run a sudo command from the agent’s prompt (in Claude Code: ! sudo …) and confirm it with a finger. I keep it off for the login and lock screens: at login you need the password anyway to unlock the keyring, and on my ThinkPad the reader there mostly gets in the way.

On Ubuntu (needs fprintd and an enrolled finger, fprintd-enroll):

# 1. remove fingerprint from the shared stack (login, lock screen, su, ...)
sudo pam-auth-update --disable fprintd
# 2. add it back for sudo only: finger first, password as fallback
sudo sed -i 's/^@include common-auth/auth\tsufficient\tpam_fprintd.so max-tries=3 timeout=10\n&/' /etc/pam.d/sudo
# 3. hide the fingerprint option on the GDM login screen
[ -f /etc/dconf/profile/gdm ] || printf 'user-db:user\nsystem-db:gdm\nfile-db:/usr/share/gdm/greeter-dconf-defaults\n' | sudo tee /etc/dconf/profile/gdm
sudo mkdir -p /etc/dconf/db/gdm.d
printf '[org/gnome/login-screen]\nenable-fingerprint-authentication=false\n' | sudo tee /etc/dconf/db/gdm.d/90-no-fingerprint
sudo dconf update

Keep a root shell open (sudo -i) while you edit PAM files, in case you lock yourself out. On a Mac the same idea is one line, and only for sudo by design: sed 's/^#auth/auth/' /etc/pam.d/sudo_local.template | sudo tee /etc/pam.d/sudo_local enables Touch ID.

One catch: commands run from an agent have no terminal, and sudo refuses to authenticate without one (“a terminal is required”), before the fingerprint module is even asked. The fix is to give it a fake terminal with script. I keep this as a tiny ~/.local/bin/fsudo, and then ! fsudo apt upgrade just asks for a finger:

#!/bin/bash
# fsudo — sudo for places without a terminal (Claude Code's `!`, agents).
exec script -qec "sudo $(printf '%q ' "$@")" /dev/null

(That is the Linux script; on macOS the syntax is script -q /dev/null sudo ….)

Tested on the ThinkPad (Ubuntu, 8 November 2026): ! fsudo apt upgrade typed into Claude Code showed “Place your right index finger on the fingerprint reader”, one touch, and apt ran as root. Because apt now thinks it has a terminal it prints its progress counters, which pile up as noise in the agent’s output; fsudo apt-get -q … is quieter. And remember that apt upgrade alone does not refresh the package lists: run apt update first.
